Support

Mirrorly is free and open source, maintained in the open on GitHub. The fastest way to get help, report a bug or ask for a feature is to open an issue.

Reporting a bug

Include as much of this as you can:

  • Your Firefox version, and Mirrorly's version from about:addons.
  • The site, the device and browser chosen in Mirrorly, and whether the problem is in one view or in syncing between them.
  • What you did, what you expected, and what happened instead.
  • A screenshot from the phone (the Screenshot button) and, if it helps, one from your real phone to compare.

Common questions

Is it the same as the phone?

Very close, but not identical. The page is drawn by Firefox's engine, not Safari's WebKit or Chrome's Blink, so engine-specific CSS can differ. Mirrorly gives the page the phone's screen size, user agent, pixel ratio, text size and safe areas, and turns off hover, so layouts match in the vast majority of cases. The page gets touch events as well as the mouse's, and pinch-zoom isn't emulated.

Does it work on localhost?

Yes. Any http or https page works, including localhost, addresses on your network and staging servers.

How do I find something from the desktop page on the phone?

Right-click it and choose Show in Mirrorly. Each phone scrolls to it and outlines it, or says if the mobile layout leaves it out.

A site won't load, or keeps reloading itself.

Some sites refuse to be shown inside a frame, or detect the phone user agent and redirect. Mirrorly stops a page that reloads itself more than six times in three seconds and shows a message. Turning off Phone user agent in the settings sometimes helps.

It doesn't work on addons.mozilla.org.

Firefox doesn't let any extension run on addons.mozilla.org and a few other Mozilla sites, so Mirrorly shows a message there instead.

Do pages I'm signed in to work?

Yes. The phones use the same cookies as your tabs, so if you're signed in on the desktop, you're signed in in the phone too. Dashboards, admin panels and other pages behind a login work in the mobile view.

How is it different from Responsive Design Mode?

Firefox's Responsive Design Mode resizes your tab to a phone's width. Mirrorly keeps the desktop page as it is and shows the phone beside it (or two phones), with scrolling, taps, typing and pages kept in sync. It also draws what a real phone adds on top of the page: the frame, the browser's bars, the keyboard and the safe areas, measured from real phones, plus iOS's Text Size.

The keyboard doesn't open.

Like iOS, the keyboard only opens for a field you tapped, not one the page focused by itself. It also needs Show soft keyboard on, and portrait.

Where do screenshots go?

To a Mirrorly folder in your Downloads folder, named after the device, browser and time. The Screenshot menu offers the phone with its frame, just the page as it's shown, or the whole page.

Feature requests

Open an issue describing what you'd like it to do and why. Screenshots from a real phone help a lot for anything visual.

Contact

Issues are the best place for anything about Mirrorly, so the answer helps the next person too: github.com/dazecoop/mirrorly/issues.
